# Kestrel Credit Appraisal Copilot: Jobs To Be Done

Status: prototype scope. Synthetic data only. The copilot prepares credit files. It never approves, rejects or sanctions a loan. Principle: rules for certainty, AI for assistance, humans for decisions.

## Scope

Pilot cases are SME working-capital loans under ₹25 lakh. The pilot cohort is 6 analysts, 3 relationship managers, 1 credit manager and 1 owner in the prototype. Amounts from ₹10 lakh to ₹2 crore exist in the portfolio; amounts of ₹25 lakh and above are shown as outside pilot scope.

## Primary pilot measure

Median hands-on preparation time per eligible application. Illustrative baseline is 6 analyst-hours (simulated estimate, to be validated). Provisional target is 3 analyst-hours or less.

Guardrail measures: material discrepancy escape rate, CAMs returned for factual error, autonomous decisions (must be zero), production LOS writes (must be zero), Gross NPA within the 3.5% board limit.

Client-level outcome monitored, not promised: 18-day median from application to decision.

## Persona 1: Relationship Manager

### Primary job

When a business applies for a working-capital loan, get every required document in once and in full, so the file moves to credit without a second request.

### Functional jobs

Sign in securely. View assigned applications. Create or open an application. Upload documents against the checklist. View the required checklist. Identify missing, invalid, unreadable or expired documents. View completeness status. Receive actionable notifications. Generate, edit and send follow-up drafts. Track outstanding documents. Monitor application progress. View full application history.

### Emotional jobs

Feel in control of the customer relationship. Avoid appearing unprofessional to the client. Know quickly whether a deal is at risk.

### Supporting jobs

Know which applications are waiting on the customer and which are waiting on credit. Keep a record of what was requested and when.

### Current pain points

Credit asks for the same documents repeatedly. The RM learns about a missing item late. Outstanding documents are tracked across phone calls and emails. Deals are lost during waiting time.

### Desired outcomes

Fewer document request rounds per file. One consolidated outstanding list. Faster customer replies. Clear visibility of each file's stage.

### Triggering events

A new application is assigned. A document is uploaded or rejected. A document expires. An analyst raises a query. A deadline passes with items outstanding.

### Expected system behaviour

The checklist is generated by deterministic rules for the loan product. Each upload is validated for type, period and readability on submission. The RM sees completeness percentage and the exact missing items. Follow-up drafts are generated from the outstanding list and are never sent without the RM's action. Every action is logged.

### Success criteria

Document request rounds per file fall. First-submission completeness rises. The RM can state the status of any file within 30 seconds.

## Persona 2: Analyst

### Primary job

Turn a complete loan file into a verified, reconciled spreading and draft CAM in as little hands-on time as possible, with every number traceable to its source page.

### Functional jobs

View assigned files. Access uploaded documents. Review OCR and extraction results. View extracted bank statement and GST fields. See field-level confidence. Navigate to the source page and evidence. Review bank versus GST reconciliation. Identify and resolve discrepancies. Correct extracted fields. Review ratios computed by deterministic code. Generate and edit the draft CAM. Sign verification and submit to the Credit Manager.

### Emotional jobs

Trust the numbers without re-checking every line. Feel accountable for a signed verification. Avoid the tedium of retyping.

### Supporting jobs

See what changed since the last session. Understand why a field was flagged. Hand over an unresolved file cleanly.

### Current pain points

Retyping bank statements and GST returns into the spreading sheet. Searching for the right page. No link between a figure and its source. Reconciliation done by hand. CAM drafted from scratch.

### Desired outcomes

Lower preparation time. Fewer transcription errors. Reliable source links. Reconciled turnover with explained gaps.

### Triggering events

A file reaches verification. Extraction completes. A discrepancy is raised. A Credit Manager returns the file.

### Expected system behaviour

Fields at or above the configured confidence threshold are auto-accepted but remain visible and editable. Fields below it are flagged. Each value opens its source page with the region highlighted. Reconciliation and ratios use deterministic code. The draft CAM cites a source for every factual sentence; uncited sentences are highlighted. Submission is blocked until verification is signed, material discrepancies are resolved and no uncited statements remain.

### Success criteria

Median hands-on time moves toward 3 analyst-hours after validation. Correction rate on auto-accepted fields stays within tolerance. No CAM reaches credit review with an unresolved material discrepancy.

## Persona 3: Credit Manager

### Primary job

Decide whether a verified CAM is ready for the existing sanction process, using evidence the analyst has already checked, and return it when it is not.

### Functional jobs

View applications awaiting review. Open the CAM. Review analyst verification history. Inspect supporting evidence. Review discrepancies and flags. Examine financial summaries. Request clarification. Record comments. Return the file for correction or complete review.

### Emotional jobs

Confidence that the numbers are sound. No surprises at committee. Ownership of the judgement.

### Supporting jobs

Compare the CAM against source pages. See who changed what. Hand the file to sanction with a clear rationale.

### Current pain points

CAMs arrive without evidence trails. Verification history is scattered across emails. Flags are unclear. Rework loops are slow.

### Desired outcomes

Faster, evidence-based reviews. Fewer rework loops. A complete rationale on record for every review.

### Triggering events

An analyst submits a CAM. An analyst resubmits after a return. A flag is escalated.

### Expected system behaviour

The CAM is shown beside its evidence, verification history and open flags. Any citation opens its source. Review actions are recorded with comments and timestamps. The review screen states that the copilot does not sanction loans. Completing review produces a reference for the manual LOS sanction step.

### Success criteria

Review cycle time falls. Returns for missing evidence fall. Every completed review has a recorded rationale.

## Persona 4: Owner and Administrator

### Primary job

Operate the AI system safely: see what it did, what it cost, how well it performed and who changed what, and make authorised, reversible changes to models and prompts.

### Functional jobs

Monitor all applications and statuses. Manage users and roles. Review agent executions and failures. View tokens and cost at every level, from individual LLM call to daily and monthly totals. Compare models. Configure primary and fallback models. Edit and version prompts. Review evaluation results. Inspect audit logs, access logs and security events. Monitor system health and API performance.

### Emotional jobs

Confidence that nothing changes silently. Ability to explain cost to the CEO and CFO. Ability to show the CRO and CISO that controls work.

### Supporting jobs

Export reports. Respond to incidents. Prepare access reviews. Plan capacity.

### Current pain points

No per-call cost visibility. Model changes require a code deployment. Prompts are edited without history. Audit logs are hard to read. Failures are discovered by users.

### Desired outcomes

Every cost, token, model change, prompt change and access change is visible, attributable and reversible. Nothing in the audit trail can be edited.

### Triggering events

Monthly cost review. Provider incident. Evaluation regression. Security alert. Request to change a model or prompt. Access review.

### Expected system behaviour

Every configuration change follows a versioned change request with validation, testing, second-person approval, an effective time and an audit event. Audit events and LLM call records are append-only. The Owner has no credit-action rights and cannot approve their own proposals.

### Success criteria

Every LLM call traces to an application and task. Cost totals reconcile with token counts. Every configuration change has an approver and an audit reference. No audit event is missing or editable.

## Role and permission summary

RM: creates applications, uploads documents, sends follow-ups. Analyst: edits extraction, resolves discrepancies, generates and submits CAM. Credit Manager: returns or completes review. Owner: administers, views all, changes models and prompts only through two-person approval, cannot act on credit files.

## Out of scope for the prototype

Autonomous credit approval or rejection. Policy or scorecard modification. LOS writes. Customer-facing approval messages. Real customer data. Real integrations with CRM, LOS or OCR vendors.
